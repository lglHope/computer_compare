# 新机型引入测试计划与方案

**文档角色**：云解决方案架构师  
**业务背景**：芯片设计与制造，OPC / Mask（MDP、Fracture、Inspection）  
**触发原因**：现有算力机型供给不足，需引入候选机型并完成可量产验证  
**版本**：v1.0  

---

## 1. 目标与原则

### 1.1 测试目标

1. 验证候选机型在 **规格、性能、稳定性、结果正确性、许可证与调度兼容、成本** 上可替代或优于现有机型。
2. 给出明确的 **Go / No-Go** 结论与引入建议（全量替换、混部、仅特定队列）。
3. 输出可复现数据：同一套脚本、同一金标、同一存储路径，基线与候选各跑不少于 3 次。

### 1.2 非目标

- 不在本阶段做全工艺全产品覆盖（金标代表层即可）。
- 不把云厂商营销跑分作为准入依据。
- 不在未通过结果一致性门禁前把候选机型接入量产队列。

### 1.3 设计原则

| 原则 | 落地方式 |
|------|----------|
| 业务优先 | 微基准用于定位瓶颈；最终以 OPC/Mask 作业墙钟、单位成本、结果一致性为准 |
| 公平对比 | 相同 vCPU/内存档位、相同镜像、相同共享存储、相同许可证、相同并发 |
| 可复现 | 配置即代码；结果落盘 JSON；禁止手工改环境后直接对比 |
| 安全合规 | 金标数据不出安全域；测试 VPC 与量产隔离；日志脱敏 |
| 分阶段放量 | 实验室 → 小流量影子队列 → 指定产品线 → 全量 |

## 2. 范围与对照

### 2.1 对照设计

| 组别 | 说明 |
|------|------|
| Baseline | 现网主力机型（算力不足的那一档） |
| Candidate | 拟引入新机型（同规格或更高规格需在报告中归一化） |
| Optional | 若新机型核数/内存不同，按「单核吞吐 + 整机作业墙钟 + 元/作业」三维对比 |

### 2.2 测试环境冻结项

- OS 与内核版本、NUMA/HT 开关、C-State、CPU governor
- EDA 工具版本、许可证服务器、环境变量、PDK/工艺包
- 共享存储挂载参数（NFS/nconnect、Lustre stripe、GPFS block）
- 网络：同可用区、同交换机域优先；跨 AZ 单独记一章
- 调度器队列、cgroup、超售比（测试期超售必须为 0）

### 2.3 业务负载画像（用于选型）

**OPC**

- 多核 OpenMP/MPI，核间同步频繁
- 通常 **内存带宽 / LLC** 瓶颈，而非纯 FLOPS
- 单作业内存常见 128 GB～2 TB，对 NUMA 敏感
- 读写大量中间层与版图切片；许可证心跳对网络抖动敏感

**Mask（MDP / Fracture / Inspection）**

- 超大 GDS/OASIS（数十 GB～TB 级）顺序读 + 散列写
- 进程数通常少于 OPC，单线程/少线程性能仍重要
- 结果正确性要求高（hash / XOR / 工具自带 DRC 级校验）
- 本地 NVMe 作 scratch 时，磁盘 QoS 与持久化盘不要混测

## 3. 阶段划分

```
P0 规格与环境验收  →  P1 微基准  →  P2 存储/网络
        →  P3 代理负载（本套件）  →  P4 真实金标
        →  P5 规模与调度  →  P6 稳定性  →  P7 成本与运维  →  决策
```

| 阶段 | 时长（建议） | 退出标准 |
|------|----------------|----------|
| P0 | 0.5 天 | 规格与宣称一致；指令集/内存/盘/网卡符合 EDA 最低要求 |
| P1–P3 | 1～2 天 | 微基准与代理负载无红灯；定位瓶颈（CPU/BW/IO/Net） |
| P4 | 3～7 天 | 金标墙钟、结果一致性、许可证全部通过 |
| P5 | 2～3 天 | 多节点、队列混部、突发扩容可用 |
| P6 | 48～72 小时 | 无 ECC/宕机/性能衰减超阈值 |
| P7 | 1 天 | TCO、交付周期、运维手册完成 |

## 4. 测试用例

### 4.1 P0 规格与兼容性

| ID | 用例 | 方法 | 通过标准 |
|----|------|------|----------|
| P0-01 | vCPU/内存/盘/网卡 | `collect_sysinfo.sh` | 与 `eval.yaml` 宣称误差 ≤ 2% |
| P0-02 | CPU 型号、主频、AVX2/AVX-512、AES | lscpu / /proc/cpuinfo | 满足工具发行说明 |
| P0-03 | NUMA 拓扑 | numactl -H | 节点数、每节点内存符合预期；无意外绑核 |
| P0-04 | 内核、glibc、OFED/EFA | uname, ldd | 与现网镜像一致或已签核 |
| P0-05 | 时间同步、主机名、DNS | chrony, getent | NTP 偏移 < 50 ms |
| P0-06 | 许可证连通 | 工具 `lmstat` 或端口探测 | 握手 < 门禁延迟 |

### 4.2 P1 CPU / 内存

| ID | 用例 | 方法 | 关注指标 |
|----|------|------|----------|
| P1-01 | 单核 CPU | sysbench 1 线程 + taskset 绑核 | events/s |
| P1-02 | 多核 CPU | sysbench 满逻辑核；并跑 25%/50% 扩展比 | 整机 events/s、parallel_efficiency |
| P1-03 | 单核内存带宽 | STREAM 1 线程 + 绑核 | Copy/Scale/Add/Triad GB/s |
| P1-04 | 整机内存带宽 | STREAM 满核 OpenMP | 同上，反映内存控制器聚合带宽 |
| P1-05 | NUMA 本地 vs 远端 | numactl --cpunodebind | 远端衰减不超过门禁 |

### 4.3 P2 存储与网络

| ID | 用例 | 方法 | 关注指标 |
|----|------|------|----------|
| P2-01 | 本地 NVMe | fio 顺序/随机 | 带宽、IOPS、尾延迟 p99 |
| P2-02 | 共享存储（版图盘） | fio 模拟大文件顺序读 + 多作业 | 单作业与 8/16 作业聚合 |
| P2-03 | scratch 生命周期 | 创建/删除 100 GB 临时文件 | 无卡死、无空间泄漏 |
| P2-04 | 节点互访 | iperf3 TCP/UDP | 带宽 ≥ 规格 80%，重传率低 |
| P2-05 | 到许可证/存储时延 | ping / 应用探测 | 符合 gates.yaml |

### 4.4 P3 业务代理负载（无许可证也可跑）

| ID | 用例 | 脚本 | 模拟什么 |
|----|------|------|----------|
| P3-01 | OPC 代理 | `bench_opc_proxy.py` + `sample_hostload.py` | 2D stencil；同步采 CPU/内存/磁盘/网络 |
| P3-02 | Mask 代理 | `bench_mask_proxy.py` + `sample_hostload.py` | 大文件扫描写回；同步采主机负载 |

代理负载 **不能** 替代金标，仅用于快速筛掉明显不合格机型。

### 4.5 P4 真实金标（准入核心）

在 `workloads/golden_cases.yaml` 登记用例，由 `run_eda_golden.sh` 调用。

| ID | 类型 | 建议用例构成 |
|----|------|----------------|
| P4-01 | OPC 小 | 1 层、数小时级，用于调试环境 |
| P4-02 | OPC 中 | 典型产品层，现网 P50 作业 |
| P4-03 | OPC 大 | 现网 P90 内存/墙钟作业 |
| P4-04 | Mask MDP | 标准 tapeout 数据包 |
| P4-05 | Fracture | 与量产同一 fracture deck |
| P4-06 | 结果一致性 | hash / 工具 compare / XOR |

**结果一致性规则（建议）**

- Mask：输出文件 hash 必须一致，或官方 compare 零差异。
- OPC：若工具非 bit-exact，采用签核容差（edge placement / 指定分层 XOR 面积），由工艺/OPC 团队书面确认，架构侧不得自行放宽。

### 4.6 P5 规模、调度、突发

| ID | 用例 | 通过标准 |
|----|------|----------|
| P5-01 | 单节点满核 1 作业 | 无 OOM、无异常降频 |
| P5-02 | 单节点多作业打包 | 与现网 packing 策略一致时墙钟退化可接受 |
| P5-03 | 16/32 节点同时提交 | 调度器识别新机型；无幽灵节点 |
| P5-04 | 弹性扩容 | 从 0 到 N 台就绪时间 ≤ 门禁 |
| P5-05 | 抢占/故障注入（可选） | 作业可重入；中间结果不污染金标盘 |

### 4.7 P6 稳定性

| ID | 用例 | 时长 | 失败条件 |
|----|------|------|----------|
| P6-01 | 循环跑中等金标 | 48～72 h | 宕机、kernel panic、ECC 不可纠正 |
| P6-02 | 性能漂移 | 同上 | 墙钟相对首次中位数恶化 > 8% |
| P6-03 | 硬件日志 | dmesg, mcelog, 云监控 | 出现不可纠正内存/磁盘错误即否决 |

### 4.8 P7 成本与运维

- 计算：墙钟 × 机时单价 × 平均重跑率
- 存储：scratch 与对象存储流出
- 网络：跨 AZ / 专线（若有）
- 运维：镜像制作、扩容失败率、厂商 SLA、备货周期
- 输出：**元/OPC 层**、**元/Mask 数据包**，以及相对基线的百分比

## 5. 门禁（摘要）

详细阈值见 `config/gates.yaml`。默认建议：

| 类别 | Go 条件 |
|------|---------|
| 规格 | 与配置宣称一致 |
| OPC 金标墙钟 | ≤ 基线 × 1.05（同档位）或单位成本 ≤ 基线 × 0.95 |
| Mask 金标墙钟 | ≤ 基线 × 1.08（I/O 型允许略宽） |
| 结果 | Mask 必须一致；OPC 在签核容差内 |
| STREAM | ≥ 基线 × 0.90（内存型作业强相关） |
| 共享存储 p99 | 不超过基线 × 1.20 |
| 稳定性 | 72 h 零严重硬件事件 |
| 许可证 | 全用例无 license wait 超时 |

任一 **P4 结果一致性** 或 **P6 不可纠正硬件错误** 为否决项，不进入混部。

## 7. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 新 CPU 导致 OPC 数值漂移 | 提前与工具商确认；金标 compare；必要时锁指令集 |
| 共享存储成为瓶颈 | 分「本地盘 / 共享盘」两套成绩；避免把存储瓶颈算到 CPU 头上 |
| 超售或noisy neighbor | 测试队列独占；记录邻居监控 |
| 许可证被测光 | 独立测试 license 或错峰；记录 wait 时间并剔除污染样本 |
| 数据出境/泄密 | 测试安全域；金标只读副本；禁用公网 |
| 供应仍不足 | 评估第二候选；混部策略；作业分级排队 |

## 8. 决策模板

测试结束后，`compare_report.py` 生成报告，人工补决策：

1. **全量引入**：P0–P6 全绿，成本不差于基线。
2. **有限引入**：仅 OPC 或仅 Mask 队列；或仅中小作业。
3. **暂缓**：性能不足或结果不一致，列改进项（换规格、调 NUMA、换盘型）。
4. **否决**：硬件错误、正确性失败、供应/合规不可接受。

引入后 2 周为观察期：现网 P50/P90 墙钟、失败率、重跑率与基线队列对比。
